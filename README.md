Бай: зөвхөн `http://localhost:3000` ([server.js](server.js), Express). Ачаалал: 20 VU, VU бүр нэг давталтад `/cart/add`, `/report`, `/pay`-г нэг нэгээр дуудаад 1с хүлээнэ.

## 1. Чанарын сценариуд (6 хэсэгтэй формат)

### Performance: `/cart/add`

| Хэсэг | Агуулга |
|---|---|
| Тойм | Хэвийн ачааллын үед хэрэглэгч бараа сагсанд нэмэхэд хариу хурдан ирэх |
| Системийн төлөв | API хэвийн ажиллаж байна. `/report`, `/pay` нь зэрэг ачаалалтай |
| Орчны төлөв | localhost, Node.js нэг процесс, хэвийн ачаалал: **20 VU**, ≈15 хүсэлт/с `/cart/add` руу, 1 минут |
| Гадаад өдөөлт | Хэрэглэгч "Сагсанд нэмэх" дарна → `POST /cart/add` |
| Шаардлагатай хариу | `200 OK`, `{ ok: true }` |
| Хэмжүүр | 1 минутын цонхонд хүсэлтийн **95% нь 20ms-ээс**, **99% нь 50ms-ээс** хурдан |

### Reliability: `/pay`

| Хэсэг | Агуулга |
|---|---|
| Тойм | Хэвийн хэрэглэгчийн төлбөрийн үйлдэл найдвартай амжилттай болох |
| Системийн төлөв | API хэвийн ажиллаж байна. Төлбөрийн gateway хааяа timeout өгдөг (~5%) |
| Орчны төлөв | localhost, **20 VU**, ≈15 хүсэлт/с `/pay` руу, 1 минут |
| Гадаад өдөөлт | Хэрэглэгч "Төлөх" дарна → `POST /pay` |
| Шаардлагатай хариу | `200 OK`, `{ paid: true }`. Алдаа гарвал `500` ба тайлбартай JSON |
| Хэмжүүр | **POFOD** (нэг хүсэлт амжилтгүй болох магадлал) = error rate **< 8%** (1 минутын цонх) |

### Availability: сервер унах ба сэргэх

| Хэсэг | Агуулга |
|---|---|
| Тойм | Сервер гэнэт зогсоод дахин асахад үйлчилгээ хэр хурдан сэргэх, нийт хэр хүртээмжтэй байх |
| Системийн төлөв | API хэвийн ажиллаж, 20 VU ачаалалтай байна |
| Орчны төлөв | localhost, 2 минутын тест. Сервер дунд нь **10 секунд** зогсоно |
| Гадаад өдөөлт | **Эвдрэл (crash):** серверийн процесс гэнэт зогсоно (Ctrl+C / kill) |
| Шаардлагатай хариу | Зогсолтын үед хүсэлтүүд шууд алдаа (connection refused) буцаана, гацахгүй. Сервер дахин асмагц хүсэлтүүд хэвийн `200` болно |
| Хэмжүүр | 2 минутын цонхонд амжилттай хүсэлтийн хувь (availability) **≥ 90%**. Дахин асаасны дараа сэргэх хугацаа **≤ 15с** |

### Нэмэлт (4 дэх) сценарио: `/report` performance

| Хэсэг | Агуулга |
|---|---|
| Тойм | Хүнд тайлан хэвийн ачаалалд хүлээгдэх хугацаандаа гарах |
| Системийн төлөв / орчин | Хэвийн, localhost, 20 VU, 1 минут |
| Гадаад өдөөлт | `GET /report` |
| Шаардлагатай хариу | `200 OK`, `{ rows: 20000 }` |
| Хэмжүүр | Хүсэлтийн **95% нь 450ms-ээс** хурдан |

**Сайн сценариогийн 5 шинжээр шалгахад:**
- **Итгэмжтэй:** тоонууд хэмжилтэд суурилсан.
- **Үнэ цэнэтэй:** хэрэглэгчийн бодит үйлдлүүд (сагс, төлбөр).
- **Тодорхой:** endpoint, ачаалал, цонхыг нэрлэсэн.
- **Нарийн:** p95/p99 болон хувиар илэрхийлсэн.
- **Ойлгомжтой:** нэг сценарио нэг хэмжүүрт төвлөрсөн.

## 2. SLO

| Сценарио | SLI (юуг хэмжих) | Босго | Цонх / нөхцөл | k6 threshold ([slo-test.js](slo-test.js)) |
|---|---|---|---|---|
| Performance | `/cart/add` latency | **p95 < 20ms**, **p99 < 50ms** | 20 VU тогтмол, 1 мин | `http_req_duration{name:cart}: ['p(95)<20', 'p(99)<50']` |
| Reliability | `/pay` error rate | **< 8%** | 20 VU, 1 мин | `http_req_failed{name:pay}: ['rate<0.08']` |
| Availability | бүх хүсэлтийн амжилтын хувь (checks) | **≥ 90%** (k6-д `> 0.90`) | 20 VU, 2 мин, 10с зогсолт | `checks: ['rate>0.90']` |
| Нэмэлт | `/report` latency | **p95 < 450ms** | 20 VU, 1 мин | `http_req_duration{name:report}: ['p(95)<450']` |

**Босго сонгосон үндэслэл:**
- **Performance:** урьдчилсан 15 секундын хэмжилтэд `/cart/add` p95 ≈ 4ms гарсан. Зааврын 200ms нь юу ч хэмжихгүй сул босго болно. Тиймээс 5 дахин нөөцтэй 20ms-ийг сонгосон: регресс (жишээ нь DB дуудлага нэмэгдэх) гарвал барьж чадна.
- **Reliability:** серверт 5% алдаа суулгасан. 1 минутад ~800 хүсэлт байхад санамсаргүй хэлбэлзэл ±0.8% орчим байдаг тул 8% бол бодитой, гэхдээ алдаа 2 дахин өсвөл барих босго.
- **Availability:** 2 минутад 10с зогсолт ≈ 8.3% цаг. 90% нь энэ туршилтыг "ирмэг дээр" шалгах босго.
- **Нэмэлт:** `/report` хамгийн ихдээ 400ms хүлээдэг. Үүн дээр 50ms нөөц нэмсэн.

**Error budget (цагаар):** 2 мин × (1 − 0.90) = 120с × 0.10 = **12 секундийн "эвдрэх эрх"**.
